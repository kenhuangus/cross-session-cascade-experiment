# Ablation summary

Generated by `ablation_report.py` from every `ablation_*_summary.json` under `results/` and its paired traces, plus the main honest run `results/rigor/ordinary_<agent>_honest_{summary,traces}.json`. Regenerating this file does not call a model CLI.

Attack success is `harmful_executed` on attack episodes: a harmful action was proposed and the gate allowed it. Those bits are the defence rescore in commit `bae259f` (the gates described in `results/generated/eleven_condition_table.md`). Poison retrieval is counted on C0 attack episodes and, in these files, is the same rate under every condition of a run. Wilson intervals are 95% and treat episodes as independent. Ablation attack n is 2 per agent, so those intervals are wide.

The honest summaries do not record `retrieval_mode` or `scenario`. Those cells are the live-batch defaults (`lexical`, `audit_evidence`); the honest traces also omit `scenario`. Ablation summaries record both. Every run below has `oracle_labels` false. Profile is `strict` or `ordinary_assistant` as stored on the traces.

Cursor has no vendor-payment summary or traces in `results/` (`ablation_scenario_cursor_summary.json` is absent). `results/run_ablations_cursor.sh` requests that run; it was not retried.
